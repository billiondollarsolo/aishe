# Claude Code compatibility — live validation

**Goal:** Can off-the-shelf Claude Code artifacts (Agent Skills and slash

## Artifacts under test (real, unmodified)

| Kind | Source | Installed as |
|------|--------|--------------|
| Agent Skill | [`anthropics/skills` → `internal-comms`](https://github.com/anthropics/skills/blob/main/skills/internal-comms/SKILL.md) | `~/.config/aishe/skills/internal-comms/SKILL.md` |
| Agent Skill | [`anthropics/skills` → `brand-guidelines`](https://github.com/anthropics/skills/blob/main/skills/brand-guidelines/SKILL.md) | `~/.config/aishe/skills/brand-guidelines/SKILL.md` |
| Slash command | [`wshobson/commands` → `tools/code-explain`](https://github.com/wshobson/commands/blob/main/tools/code-explain.md) | `~/.config/aishe/commands/code-explain.md` |

These files were downloaded byte-for-byte and copied in with **no edits**. They
carry frontmatter keys aishe doesn't use (`license:` on the skills, `model:` on
the command); aishe reads `name`/`description` and ignores the rest.

## Format compatibility

- **Skills:** Claude's `SKILL.md` = aishe's skill file: `name` + `description`
  frontmatter + Markdown body. ✅ Identical.
- **Commands:** Claude's command `.md` = aishe's command file: optional
  frontmatter + body with `$ARGUMENTS`/`$1`. ✅ Identical. (`code-explain.md`
  has no `description`, so aishe falls back to a generated one — still loads.)

## Results

### Discovery / parsing — PASS

```
$ aishe -c "/skills"
model-invoked skills (yolo mode):
  brand-guidelines  —  Applies Anthropic's official brand colors and typography ...
  internal-comms    —  A set of resources to help me write all kinds of internal communications ...

$ aishe -c "/commands"
custom slash-commands:
  /code-explain  —  custom command /code-explain
```

Both real skills parse (descriptions surfaced verbatim from frontmatter); the
real command registers. `license:`/`model:` keys are ignored without error.

### Skill auto-selection + progressive disclosure (yolo) — PASS

```
$ aishe --mode yolo -c "Write a short 3P (Progress, Plans, Problems) update
                        for my team about the aishe shell project. Save to update.md"
  📖 skill: internal-comms
  ⚡ create update.md with 3P update: cat > update.md <<'EOF' ...
Created update.md with a concise 3P (Progress, Plans, Problems) update ...
```

The model — given only each skill's `name: description` — **autonomously chose
`use_skill: internal-comms`**, aishe loaded the skill body into context
(progressive disclosure), and the model produced `update.md` in the skill's
exact **Progress / Plans / Problems** structure. This is the full Claude Code
skills contract working against a non-Anthropic model.

### Custom slash command with `$ARGUMENTS` — PASS

```
$ aishe --mode yolo -c "/code-explain explain what 'awk \"{s+=\$1} END {print s}\"' does"
... rendered markdown explanation of the awk accumulator one-liner ...
```

aishe expanded the real `code-explain` template (`$ARGUMENTS` → the user's
text), sent the ~800-line code-education prompt to the model, and rendered the
markdown answer. (The model's interpretation of the argument was imperfect, but
that is a model/prompt artifact — the **command pipeline** worked end-to-end.)

## Verdict

✅ **Real Claude Code Agent Skills and slash commands run in aishe unmodified.**
Drop a skill folder into `~/.config/aishe/skills/` or a command `.md` into
`~/.config/aishe/commands/` and they work — discovery, model-driven
`use_skill`, progressive disclosure, and `$ARGUMENTS` templating all verified
live against `gpt-oss-120b`.

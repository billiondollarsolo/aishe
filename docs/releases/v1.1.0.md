# AIShe v1.1.0 candidate — start quickly, keep control

Prepared on 2026-10-10. This is a candidate record, not a published release or a
claim that all qualification has passed. Cargo identifies the next release as
1.1.0; v1.0.0 remains the latest public release until publication is explicitly
performed. The installer resolves that published release, so current source can
have features unavailable in an older downloaded binary.

## Everyday adoption

The native installer downloads and verifies AIShe alone. API-key and local-model
requests use the included engine. A subscription OAuth account explicitly opts
into the pinned legacy runtime; `--backend` can install and live-verify it in
advance. Runtime failures on that opt-in path preserve the current executable,
and ordinary binary upgrades preserve configuration, credentials, tasks,
history, journals, and existing runtime versions.

```sh
curl -fsSL https://raw.githubusercontent.com/billiondollarsolo/aishe/main/install.sh | sh -s -- --launch
```

`--launch` uses the installed absolute executable and the controlling terminal.
PATH guidance appears before setup; an unattended install prints a runnable
command. `--setup --launch` runs setup first. No installer action changes your
shell startup file or account's login shell.

Fresh AIShe starts ordinary commands without account setup. Setup and settings
save **Keep my zsh**, **Clean AIShe**, or **Bash integration**. Keep my zsh preserves
`.zshenv`/`.zshrc`, your prompt, history, plugins, and existing widgets. Clean
AIShe provides the full native prompt with isolated startup files. Bash keeps
`.bashrc`, Readline and its prompt with the documented reduced hook tier. Existing
configurations that omit the new profile field retain the clean profile.

**Connect later** applies reviewed shell settings without a provider probe,
credential rewrite, or runtime download. `/setup` connects when you are ready;
setup's recommended behavior is ask mode. Allow and agent modes still need a
fresh grant for each live shell. Setup drafts remain resumable, and settings
show current values, unsaved changes, and what takes effect in a new shell.

For optional terminal activation, `aishe activate zsh` or `aishe activate bash`
previews the managed startup block. `--apply` installs that reviewed block with
a backup; `--remove` removes it while keeping other startup edits. Activation
is reversible and leaves the account's login shell alone.

## A capable agent inside a real shell

- Foreground, CLI, and background work use the native engine, reused provider
  connections, lazy command/skill loading, and on-demand MCP connections.
- Agent commands receive the interactive shell's current exported PATH, virtual
  environment and ordinary variables. Credentials and startup controls are
  filtered; aliases and functions stay with the user's shell.
- Native execution reports explicit completion, cancellation, failure, budget,
  and iteration outcomes. Checkpoints retain scope, model, workspace and spent
  allowances; uncertain tool effects are reconciled before resume.
- Workspace and host grants stay explicit. Functional bubblewrap is required for
  Linux workspace isolation; macOS workspace restrictions remain policy-only.

## Background work that stays quiet

A compact prompt indicator shows running work, unseen results and work requiring
attention. Ctrl-X b opens the task browser without losing the current input.
`/tasks` opens current work and `/inbox` opens **Needs you** across projects.

Background questions and exact-action approvals remain available until answered.
Leaving an approval for later is the default. Follow-ups show **queued** until
recorded in the worker's transcript, then **received**; a queued message can be
edited or removed before delivery starts.

Task results show recorded checks, unresolved items, authority, model, workspace
and remaining limits. Long prose follows that context, with scrolling cues.
Unpriced usage says its price is unknown; partially priced totals stay labeled
as partial. Model prose cannot convert a failed or stale check into a pass.

Names, pinning and archive keep a large history manageable. Opening a result
marks it seen; explicitly marking it reviewed records that distinct decision.
Both persist across shells and are tied to the exact result. New work becomes
visible again. Archiving keeps the result and its workspace.

## Continue, inspect and reuse work

- Ctrl-X d requests background continuation at a safe boundary; **g** in details
  brings the recorded context back to the terminal with its scope and budgets.
- Selective apply reviews files and text hunks alongside recorded checks. Apply
  requires the exact reviewed source/patch revision; a selected subset is labeled
  as not independently checked.
- A factual timeline distinguishes tool effects, human decisions, uncertain
  outcomes and plan notes. Workflow templates run dependency graphs in separate
  Git worktrees with bounded parallelism, budgets and recorded-check gates.
- Bare slash discovery is a bounded searchable picker; selection stages a command
  for review. Path, argument and ordinary command completion remain native.
- First-shell discovery is persisted only after the visible hint is delivered.
  Settings preview supported native prompt fields accurately.

## Shell compatibility boundaries

Interactive zsh remains the full native experience. `aishe -i` opens an explicit
interactive session; personal zsh `aishe -il` loads its login startup files.
Bash's hook is Tier B on 5.x and Tier B- on 3.2; it does not provide the native
zsh display, routing colors or identical shortcuts. Interactive Bash login mode
is refused until its startup contract is qualified.

Piped input, a script filename and `-s` execute one conventional shell program
without routing control-flow fragments to an agent. `-lc` is a conventional
login-shell command. Ordinary `-c LINE` retains AIShe's route classification;
`--agent-lines` explicitly selects the former line-by-line agent protocol.
AIShe is not offered as a `chsh`/`/etc/shells` login interpreter. Activation
replaces the interactive startup shell; exiting AIShe ends that terminal
session. Running `aishe` manually returns to the parent shell when it exits.

Personal plugin and terminal claims extend only to recorded qualification.
Synthetic PTY tests do not establish manual passes for Apple Terminal, iTerm2,
WezTerm, kitty, GNOME Terminal, VS Code or Cursor. WSL remains unqualified.

## Qualification and publication

The exact release commit must have a completed successful maintained CI run.
Every declared required job, including native Linux/macOS startup and terminal
checks, must pass. The original direct-command gate remains **100 measured
commands, 10 warmups**, with added p95 at most **max(10 ms, 10% of raw zsh p95)**.
A diagnostic profile, shorter sample or successful build cannot replace it.

Native artifacts record the full source SHA, embedded binary version/commit,
binary SHA-256, production/qualification source digest, runtime/plugin pins,
profile revision and the strict benchmark's digest. Release creation and final
publication validate both retained platform artifacts against this checkout.

The committed [qualification record](v1.1.0.qualification.json) is initially
**hold**. Paid providers, manual terminal checks and long-soak dispositions must
have actual source-bound passing evidence or an explicitly owned, time-limited
risk disposition. Supported deterministic platform failures remain a hold.
The record's production digest excludes release prose/records to avoid a hash
self-reference; source, assets, install behavior or qualification changes make
older dispositions stale.

Before publishing, update this record with the final candidate evidence and
owner decision, let that exact commit pass CI, then invoke the release workflow.
The workflow creates no draft/tag before qualification and publishes only after
all binaries, packages and runtime supply-chain artifacts complete. This work
prepares v1.1.0 and does not itself tag or publish it.

## Rollback and remaining limits

Restore verified program/runtime artifacts while preserving user state in place.
Use the [rollback guide](../release-readiness.md#binary-rollback) and verify the
rolled-back native binary; managed OAuth additionally needs its compatible
runtime verification. Do not restore an old data directory over newer tasks.

Provider availability, unknown pricing, terminal-specific behavior and macOS
policy-only containment remain visible limits. File approvals, scope grants,
checks and recorded evidence continue to be separate decisions. Full adoption
implementation and qualification tasks are in the
[readiness plan](../design/ADOPTION_RELEASE_READINESS_PLAN.md).
